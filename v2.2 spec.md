## 1. Einführung & Zielsetzung

### 1.1 Überblick

Der Schließfach-Manager ist eine Terminal-basierte Anwendung zur Verwaltung von Schließfächern, Verleihvorgängen, Finanzen und Standorten. Version 2.2 fokussiert sich auf:

- **Verbesserung der Usability:** Globale Keybind-Architektur, Window Switcher, Dialog-artige Wizards
- **Fixed-Height Dashboard Layout:** Stabiles Layout bei Terminal-Resize
- **Konfigurierbare Preise:** Pfand, Jahresgebühren, Berechnungszeitraum
- **Erweiterte Export/Import-Formate:** TOML als Default, JSON, CSV, Markdown
- **Audit-Logging:** Vollständige Nachverfolgbarkeit aller Änderungen
- **Historische Analysen:** Belegungstrend, occupancy history
- **Robuste Tests:** Unit-, Integration- und UI-Tests mit >85% Coverage
- **Vollständige Dokumentation:** Inline-Dokumentation, README, User Guide

### 1.2 Abwärtskompatibilität

- Datenbank-Migrationen sind kompatibel zu v2.0/v2.1
- Bestehende Datenbanken werden automatisch migriert
- Export-Formate bleiben rückwärts lesbar

### 1.3 Zielplattformen

- **Betriebssysteme:** Linux, macOS, Windows
- **Terminal:** Jeder moderne Terminal-Emulator mit UTF-8 Support
- **Mindestgröße:** 80x24 Zeichen (optimal: 120x40+)

```rust
// db/migrations.rs

pub fn run_migrations(conn: &Connection) -> Result<()> {
    let current_version = get_schema_version(conn)?;
    
    if current_version < 1 {
        create_initial_schema(conn)?;
    }
    
    if current_version < 2 {
        add_settings_table(conn)?;
        add_audit_log_table(conn)?;
    }
    
    if current_version < 3 {
        add_occupancy_history_table(conn)?;
    }
    
    set_schema_version(conn, 3)?;
    Ok(())
}
```

### 4.4 Status Bar

```rust
// ui/widgets/status_bar.rs

pub struct StatusBar {
    message: Option<StatusMessage>,
}

pub struct StatusMessage {
    pub text: String,
    pub level: StatusLevel,
    pub timestamp: Instant,
}

pub enum StatusLevel {
    Info,
    Success,
    Warning,
    Error,
}

impl StatusBar {
    pub fn set_message(&mut self, text: String, level: StatusLevel) {
        self.message = Some(StatusMessage {
            text,
            level,
            timestamp: Instant::now(),
        });
    }
    
    pub fn render(&self, area: Rect, buf: &mut Buffer, theme: &Theme) {
        if let Some(msg) = &self.message {
            // Auto-clear after 5 seconds
            if msg.timestamp.elapsed() > Duration::from_secs(5) {
                return;
            }
            
            let style = match msg.level {
                StatusLevel::Info => theme.status_info,
                StatusLevel::Success => theme.status_success,
                StatusLevel::Warning => theme.status_warning,
                StatusLevel::Error => theme.status_error,
            };
            
            let text = Paragraph::new(&msg.text)
                .style(style)
                .alignment(Alignment::Left);
            
            text.render(area, buf);
        }
    }
}
```

```rust
pub fn layout_dashboard(area: Rect) -> Vec<Rect> {
```

```rust
// ui/widgets/wizard.rs

pub struct WizardMessage {
    pub sender: MessageSender,
    pub content: MessageContent,
    pub timestamp: Option<String>,
}

pub enum MessageSender {
    System,
    User,
}

pub enum MessageContent {
    Question {
        text: String,
        options: Vec<WizardOption>,
    },
    Answer {
        text: String,
    },
    Info {
        text: String,
    },
}

pub struct WizardOption {
    pub label: String,
    pub value: String,
    pub metadata: Option<String>, // z.B. "(42 verfügbar)"
}

pub struct WizardRenderer {
    messages: Vec<WizardMessage>,
    current_question_index: usize,
    selected_option_index: usize,
}

impl WizardRenderer {
    pub fn render(&self, area: Rect, buf: &mut Buffer, theme: &Theme) {
        // Scrollable message history
        let history_height = area.height.saturating_sub(10);
        let question_height = 10;
        
        let chunks = Layout::default()
            .direction(Direction::Vertical)
            .constraints([
                Constraint::Length(history_height),
                Constraint::Length(question_height),
            ])
            .split(area);
        
        // Render message history (previous Q&A)
        self.render_history(chunks[0], buf, theme);
        
        // Render current question with options
        if let Some(current_msg) = self.messages.get(self.current_question_index) {
            self.render_question(current_msg, chunks[1], buf, theme);
```

```rust
pub fn log_action(
    conn: &Connection,
    action: &str,
    entity_type: &str,
    entity_id: Option<i64>,
    details: &str,
    username: &str,

        params![action, entity_type, entity_id, details, username],
    )?;
    Ok(())
}

pub fn get_recent_logs(conn: &Connection, limit: usize) -> Result<Vec<AuditEntry>> {
    let mut stmt = conn.prepare(
        "SELECT id, timestamp, action, entity_type, entity_id, details, username
         FROM audit_log
         ORDER BY timestamp DESC
         LIMIT ?1"
    )?;
    
    let logs = stmt.query_map([limit], |row| {
        Ok(AuditEntry {
            id: row.get(0)?,
            timestamp: row.get(1)?,
            action: row.get(2)?,
            entity_type: row.get(3)?,
            entity_id: row.get(4)?,
            details: row.get(5)?,
            username: row.get(6)?,
        })
    })?
    .collect::<Result<Vec<_>, _>>()?;
    
    Ok(logs)
}
```

```rust
// db/history.rs

pub fn get_occupancy_history(conn: &Connection, months: usize) -> Result<Vec<(String, f64)>> {
    let mut history = Vec::new();
    
    for month_offset in (0..months).rev() {
        let target_date = Utc::now().checked_sub_months(Months::new(month_offset as u32))
            .unwrap()
            .format("%Y-%m-01")
            .to_string();
        
        let occupied = count_occupied_on_date(conn, &target_date)?;
        let total = count_total_lockers(conn)?;
        let percent = (occupied as f64 / total as f64) * 100.0;
        
        let label = format_month_label(&target_date);
        history.push((label, percent));
    }
    
    Ok(history)
}

fn count_occupied_on_date(conn: &Connection, date: &str) -> Result<usize> {
    let count: usize = conn.query_row(
        "SELECT COUNT(*) FROM rentals
         WHERE start_date <= ?1 AND (end_date >= ?1 OR end_date IS NULL)",
        params![date],
        |row| row.get(0),
    )?;
    Ok(count)
}
```

```markdown
# Schließfach-Manager – Benutzerhandbuch

## Inhaltsverzeichnis

1. Überblick
2. Navigation
3. Dashboard
4. Verleih-Management
5. Finanzen
6. Verwaltung
7. Export & Import
8. Fehlerbehebung

## 1. Überblick

Der Schließfach-Manager hilft bei der Verwaltung von:
- Schließfächern und deren Standorten
- Verleihvorgängen (aktiv, abgelaufen, überfällig)
- Zahlungen (Pfand, Jahresgebühren)
- Historischen Daten und Trends

## 2. Navigation

### Globale Navigation

- **Window Switcher (`^`):** Öffnet eine Übersicht aller Screens. Mit `Tab` vorwärts, `Shift+Tab` rückwärts navigieren, `Enter` zum Bestätigen.
- **Dashboard-Shortcuts:** Drücke `1-5` um direkt zu spezifischen Funktionen zu springen.

### Tab-Navigation

Innerhalb von Screens mit mehreren Tabs (z.B. Verleih-Management):
- `Tab` – Nächster Tab
- `Shift+Tab` – Vorheriger Tab

### Listen & Tabellen

- `↑` / `↓` – Zeile auswählen
- `Enter` – Details anzeigen / Aktion ausführen
- `PgUp` / `PgDn` – Seitenweise scrollen

## 3. Dashboard

Das Dashboard zeigt:

### Belegung
- Gesamtanzahl Schließfächer
- Anzahl belegt/frei
- Belegung nach Größe und Standort

### Aktionen erforderlich
- Überfällige Rückgaben
- Auslaufende Verträge (binnen 30 Tagen)
- Defekte Schließfächer

### Standorte
- Belegung pro Standort

### Finanzen
- Ausstehende Zahlungen
- Einnahmen (30 Tage)

### Trend
- Belegungsverlauf der letzten 12 Monate

## 4. Verleih-Management

### 4.1 Neuer Verleih (Search)

1. Drücke `1` oder navigiere zu Verleih-Management → Search
2. Beantworte die Fragen im Wizard:
   - Standort-Präferenz
   - Größe
   - Verleihername
   - E-Mail
   - Telefonnummer
   - Startdatum
   - Pfand bezahlt?
3. Bestätige mit `Enter` nach jeder Frage
4. Nach Abschluss: Verleih wird erstellt und Schließfach zugewiesen

### 4.2 Liste (List)

- Zeigt alle aktiven Verleihvorgänge
- Sortierbar nach Datum, Name, Standort
- Filterbar nach Status

### 4.3 Verlängern (Extend)

1. Wähle Verleihvorgang aus Liste oder suche per Name/E-Mail
2. Gib neues Enddatum ein
3. Bestätige

### 4.4 Rückgabe (Return)

1. Wähle Verleihvorgang
2. Bestätige Rückgabedatum
3. Markiere Pfand als zurückgegeben
4. Verleih wird als abgeschlossen markiert, Schließfach wird frei

### 4.5 Defekt melden (Damage)

1. Wähle Schließfach
2. Gib Beschreibung des Defekts ein
3. Schließfach wird als "defekt" markiert und nicht mehr verliehen
4. Nach Reparatur: Status auf "repariert" setzen

## 5. Finanzen

### Übersicht
- Ausstehende Zahlungen
- Einnahmen (30 Tage, Jahr)
- Pfandübersicht

### Zahlungsverlauf
- Liste aller Zahlungen
- Export als CSV/TOML für Buchhaltung

## 6. Verwaltung

### 6.1 Schließfächer

- Alle Schließfächer anzeigen
- Bulk-Erstellung (z.B. 50 Schließfächer auf einmal)
- Status ändern (verfügbar, defekt, repariert)

### 6.2 Standorte

- Standorte hinzufügen/bearbeiten
- Schließfächer pro Standort anzeigen

### 6.3 Einstellungen

- **Pfandbetrag:** Standard 10.00€
- **Jahresgebühr:** Standard 24.00€
- **Berechnungszeitraum:** Monatlich oder Jährlich
- **Export-Format:** TOML (empfohlen), JSON, CSV

### 6.4 Audit Log

- Chronologische Liste aller Änderungen
- Filterbar nach Aktion, Entität, Datum

## 7. Export & Import

### Export

1. Drücke `E` in Finanzen oder Verwaltung
2. Wähle Format (TOML empfohlen)
3. Wähle Datenumfang (Alle, nur Schließfächer, etc.)
4. Gib Zielpfad ein oder verwende Default
5. Bestätige

### Import

1. Drücke `I` in Verwaltung
2. Wähle Datei
3. Wähle Konfliktbehandlung:
   - **Überspringen:** Bestehende Einträge bleiben unverändert
   - **Überschreiben:** Neue Daten ersetzen alte
   - **Mergen:** Intelligente Zusammenführung
4. Optional: Dry-Run für Vorschau
5. Bestätige

**Hinweis:** Erstelle regelmäßig Backups!

## 8. Fehlerbehebung

### Datenbank-Fehler

- **Problem:** "Database locked"
- **Lösung:** Stelle sicher, dass keine andere Instanz läuft. Prüfe Dateiberechtigungen.

### UI-Darstellungsprobleme

- **Problem:** Zeichen werden nicht korrekt dargestellt
- **Lösung:** Stelle sicher, dass dein Terminal UTF-8 unterstützt. Verwende einen modernen Terminal-Emulator.

### Import-Fehler

- **Problem:** "Invalid format"
- **Lösung:** Prüfe, ob die Datei tatsächlich im angegebenen Format ist. Validiere TOML/JSON Syntax.

### Performance

- **Problem:** Langsame Ladezeiten
- **Lösung:** Optimiere Datenbank (wird automatisch bei Start durchgeführt). Bei sehr großen Datenmengen (>10.000 Einträge) erwäge Export von alten Daten.
```

## 16. Code Style & Best Practices

### 16.1 Rust-Konventionen

- **Naming:**
  - `snake_case` für Funktionen, Variablen, Module
  - `PascalCase` für Structs, Enums, Traits
  - `SCREAMING_SNAKE_CASE` für Konstanten
  
- **Error Handling:**
  - Verwende `Result<T, E>` für fallible Operationen
  - Nutze `anyhow` für Application-Level Errors
  - Nutze `thiserror` für Library-Level Errors (optional)
  
- **Documentation:**
  - Jede public Funktion bekommt `///` doc comments
  - Jedes Modul bekommt `//!` module-level docs
  
- **Testing:**
  - Unit tests in selben File mit `#[cfg(test)]`
  - Integration tests in `tests/`

## 17. Deployment & Distribution

### 17.1 Release-Prozess

1. **Version Bump:** Update `Cargo.toml` und `CHANGELOG.md`
2. **Tag erstellen:** `git tag -a v2.2.0 -m "Release v2.2.0"`
3. **Build Release-Binaries:**
   ```bash
   cargo build --release --target x86_64-unknown-linux-gnu
   cargo build --release --target x86_64-apple-darwin
   cargo build --release --target x86_64-pc-windows-msvc
   ```
4. **Create GitHub Release** mit Binaries
5. **Optional:** Publish to crates.io

### 17.2 Plattform-spezifische Builds

```toml
# .cargo/config.toml

[target.x86_64-unknown-linux-gnu]
linker = "x86_64-linux-gnu-gcc"

[target.x86_64-pc-windows-msvc]
linker = "link.exe"
```

### 17.3 CI/CD Release Workflow

```yaml
# .github/workflows/release.yml

name: Release

on:
  push:
    tags:
      - 'v*'

jobs:
  build:
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      
      - name: Build
        run: cargo build --release
      
      - name: Package
        run: |
          cd target/release
          tar czf schließfach-manager-${{ matrix.os }}.tar.gz schließfach-manager
      
      - name: Upload Release Asset
        uses: actions/upload-release-asset@v1
        with:
          upload_url: ${{ github.event.release.upload_url }}
          asset_path: ./target/release/schließfach-manager-${{ matrix.os }}.tar.gz
          asset_name: schließfach-manager-${{ matrix.os }}.tar.gz
          asset_content_type: application/gzip
```

- 10.000 Verleihvorgänge: ~5 MB

**Performance-Ziele:**
- Startup: <500ms
- Screen-Wechsel: <100ms
- Query-Antwortzeit: <50ms (99th percentile)
- Export (10.000 Einträge): <2s

Vollständige Liste siehe `Cargo.toml`. Wichtige Abhängigkeiten:

**WICHTIG: Lies diesen Spec vollständig durch und achte darauf, dass du WIRKLICH ALLES implementierst!**

### Prioritäten:

1. **Hoch (Blocker):**
   - Dashboard fixed-height layout
   - Keys 1-5 korrekte Navigation
   - Globale Keybind Bar + Status Bar
   - Window Switcher ([^])
   - Wizard-Interaktionen vollständig funktionsfähig

2. **Mittel:**
   - TOML Export/Import
   - Konfigurierbare Preise & Billing
   - Audit-Logging vollständig

3. **Niedrig (aber erforderlich):**

   - UI-Polish & Theme
